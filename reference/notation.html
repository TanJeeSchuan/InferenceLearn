Reading the stubs: type hints

The function signatures in minfer/ carry Python type hints. They document what goes in and what comes out. Python doesn't check them at runtime.

WrittenMeansExample
ids: Tensorthe argument ids is a PyTorch tensortensor([785, 6722])
eps: floatthe argument eps is a Python float1e-06
W: dict[str, Tensor]a dictionary whose keys are strings and whose values are tensorsW["model.norm.weight"] is a (1024,) tensor
-> Tensorthe function returns a tensor

The shapes live in the docstrings, because the type hint only says "tensor". ids: (T,) under a function means that argument is 1-D with length T.

Why keepdim=True

For x of shape (2, 3), x.sum(-1) returns (2,), one total per row. PyTorch lines shapes up from the right, so dividing (2, 3) by (2,) matches the 2 totals against the 3 columns. Here that raises an error. When the sizes happen to match, it silently divides by the wrong totals, which is worse.

x.sum(-1, keepdim=True) returns (2, 1). Dividing (2, 3) by (2, 1) stretches each row's total across that row's 3 columns, so every element gets divided by its own row's total.

Worked example: softmax

softmax(z)i = exp(zi) / Σj exp(zj)

In words, the i-th output is exp of the i-th input divided by the sum of exp over all inputs.

StepCodez = [2, 1, 0]z − max = [0, −1, −2]

Both columns end with the same probabilities. Subtracting 2 shrank every exp by the same factor, e² ≈ 7.39, and the division cancels it. The right column also can't overflow, because its largest exponent is 0.
