Warm-up

From lesson 0001, from memory.

What does your zero_layer_logits return?

Logits are raw scores, shape (T, V). Softmax is a separate step, and stage 2 needs the raw logits so it can apply temperature first.

In RMSNorm, which order is right?

mean(x²): square first, then average. Averaging first lets positive and negative values cancel, which is the bug from your first attempt.

Why did a trailing space in the prompt stop the model from saying Paris?

The vocabulary has ' Paris' with the space built in. A lone ' ' token is followed by digits far more often than by 'Paris' without its space.

Your guess, checked

You guessed that the last position collects "capital of" first, then "France", and that both parts of the block take part. Geva et al. traced exactly this kind of question through a model and found the same order. Information from the relation words arrives at the last position first, and information from the subject arrives after it. Geva, Bastings, Filippova and Globerson, Dissecting Recall of Factual Associations in Auto-Regressive Language Models, EMNLP 2023. They studied GPT-2 and GPT-J, not Qwen3, so treat this as how models like Qwen3 tend to work, not a measurement of yours.

The part your guess didn't name is what happens at the ' France' position before any of that. Early MLPs there "enrich" the vector with facts about France. Then an attention head at the last position reads "Paris" out of that enriched vector. So the MLPs store facts at each position, and attention moves them between positions. That split is the whole block in one sentence.

A block makes two updates

Each block reads the running vector x and adds two updates to it.

x = x + attention(rms_norm(x))   # mix information across positions
x = x + mlp(rms_norm(x))         # transform each position on its own

Because each update gets added to x and doesn't replace it, a block can leave most of x alone and change one part. People call x the residual stream: every block reads from it and writes back into it, and its shape stays (T, 1024) the whole way through.

  1. RMSNorminput_layernorm(T, 1024)
  2. Attentionq, k, v projections, 16 heads, mask, softmax, output projection(T, 1024)
  3. Add to xfirst residual update(T, 1024)
  4. RMSNormpost_attention_layernorm(T, 1024)
  5. MLPgate and up to 3072, silu, down to 1024(T, 1024)
  6. Add to xsecond residual update(T, 1024)

Attention, with numbers

Every position makes three vectors from its x. A query q says what it's looking for. A key k says what it offers. A value v is what it hands over if chosen. Each comes from a matrix multiply, q = h @ q_proj.weight.T and so on.

weights = softmax( q kᵀ / √d + mask )
out = weights @ v

Take T = 3 positions with d = 2 numbers each.

Positionqkv
0[1, 0][1, 0][10, 0]
1[0, 1][0, 1][0, 10]
2[1, 1][1, 1][5, 5]

Row i of q @ k.T holds position i's query dotted with every key. Dividing by √2 gives the scores. The causal mask then sets every score where j > i to −∞, because a position may only look at itself and earlier positions. exp(−∞) is 0, so those entries get zero weight after softmax.

Rowscores, maskedweights = softmaxout = weights @ v
0[0.71, −∞, −∞][1, 0, 0][10, 0]
1[0, 0.71, −∞][0.33, 0.67, 0][3.3, 6.7]
2[0.71, 0.71, 1.41][0.25, 0.25, 0.50][5.0, 5.0]

Position 0 can only see itself, so it copies its own value. Position 2's query matches its own key best, so half its output comes from v₂. Each output row is a weighted average of the visible values, with the weights decided by query-key matches. Dividing by √d keeps scores from growing with the vector length. Without it, 128-number dot products get large, softmax puts nearly all the weight on one entry, and the averaging stops working. The reason is in §3.2.1 of Vaswani et al., 2017.

Qwen3's version

Qwen3 runs this with real sizes and four additions.

16 heads. q_proj makes 2048 numbers per position, split into 16 heads of 128. Each head runs its own attention on its own 128-number slice, so different heads can look for different things. Afterwards the 16 outputs get joined back into 2048 numbers, and o_proj maps them down to 1024.

8 KV heads, shared. k_proj and v_proj only make 8 heads each. Every key and value head serves 2 query heads. This is grouped-query attention, GQA. It halves the keys and values the model has to keep around, which is the whole subject of stage 3. Ainslie et al., 2023. In code, the sharing is a repeat: each KV head gets copied so the counts match before the matmul.

QK-norm. Before attention, Qwen3 runs RMSNorm over each head's 128 numbers in q and in k, with their own weights q_norm and k_norm. That's your rms_norm again, applied to the last dim.

RoPE. Rotary position embedding rotates pairs of numbers in q and k by an angle that depends on the position. That's how attention knows token order. It never changes a shape, and lesson 0003 covers how it works.

The MLP

The MLP works on each position separately. Qwen3 uses a gated version called SwiGLU.

mlp(h) = ( silu(h Wgateᵀ) ⊙ (h Wupᵀ) ) Wdownᵀ

The gate and up projections widen each position from 1024 to 3072 numbers. silu(z) = z · σ(z) is a smooth on/off switch: silu([−2, 0, 2]) = [−0.24, 0, 1.76]. Multiplying by the up projection lets the gate decide how much of each of the 3072 features passes through. The down projection maps back to 1024. Shazeer, 2020 introduces SwiGLU. The reference you will match is Qwen3MLP in modeling_qwen3.py.

Recall

After the trace, from memory.

What does the causal mask do to row 0 of the attention weights?

Position 0 can only see itself. Every other score is −∞, so softmax gives position 0 a weight of 1.

Why does q_proj output 2048 numbers when the model width is 1024?

num_attention_heads × head_dim = 16 × 128 = 2048. Qwen3 doesn't tie the attention width to the model width.

Which part of the block moves information from one position to another?

Only attention combines different positions. The MLP, RMSNorm and the residual adds all work on one position at a time.
