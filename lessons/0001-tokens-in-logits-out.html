Tokens in, logits out

Build both ends of Qwen3-0.6B and leave out the middle. About 45 minutes.

Warm-up

There are no earlier lessons to review yet, so this checks the shape intuition you said you have. Answer from memory.

E has shape (151936, 1024) and ids has shape (6,). What shape is E[ids]?

Indexing with a tensor of ids picks whole rows, one per id, in order. The 6 picked rows each keep their 1024 columns.

x is (6, 1024) and E is (151936, 1024). What shape is x @ E.T?

(6, 1024) @ (1024, 151936): the inner 1024s cancel and the outer dims survive. That is one number per (position, vocabulary entry) pair.

x is (6, 1024). What shape is x.mean(dim=-1, keepdim=True)?

Reducing the last dim with keepdim=True leaves a size-1 dim behind, so x / x.mean(-1, keepdim=True) broadcasts one value across each row. Without it you get (6,), which broadcasts against the wrong dim, or fails.

The whole job, as one function

An LLM, at inference time, is one function:

model(ids: (T,) int64) -> logits: (T, V) float

T is the number of tokens in the prompt and V is the vocabulary size: 151,936 for Qwen3-0.6B. Row t of the output holds one score per vocabulary entry: how much the model likes each candidate as token t+1, given tokens 0..t. These raw scores are logits. Softmax turns a row of logits into a probability distribution. Every number about this model in the course comes from its config.json: vocab_size 151936, hidden_size 1024, num_hidden_layers 28, tie_word_embeddings true.

Generating text means calling this function, sampling from the last row, appending the sampled id, and calling it again. That loop is stage 2. Everything after that (KV cache, batching, paging) is about making the loop cheaper. Today you build the function, minus its middle.

The pipeline, with the shapes for Qwen3-0.6B (D = 1024):

Text to ids

A tokenizer splits text into pieces from a fixed vocabulary and returns their integer ids. Qwen uses byte-level BPE, so any byte sequence can be encoded and nothing is ever "unknown". You won't write one: it doesn't affect inference speed, and the model only ever sees the ids. The Qwen3 Technical Report (§2) gives the tokenizer as byte-level BPE with 151,669 tokens. len(tok) is 151,669, but the embedding table has 151,936 rows: 267 padding rows that the tokenizer never produces.

from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained("Qwen/Qwen3-0.6B")
ids = tok("The capital of France is", return_tensors="pt").input_ids[0]
print(ids, [tok.decode(i) for i in ids])

Ids to vectors: the embedding

The embedding table E is (V, D): one learned 1024-dim vector per vocabulary entry. Embedding a token is reading its row: E[ids].

That is the same as multiplying a one-hot matrix by E: one_hot(ids, V) @ E. The two give identical results. Indexing wins because the one-hot version does T × 151936 × 1024 multiply-adds, nearly all of them by zero, just to copy T rows. For T = 6 that's about 0.9 billion multiply-adds to move 6 × 1024 numbers. Cost of the math vs. cost of moving bytes is the theme of stage 3.

The middle, skipped

Each of the 28 blocks takes a (T, D) tensor and returns another (T, D) tensor. Because the shape never changes, you can delete all of them and the two ends still connect. You'll do that today, and see what a model with nothing in the middle predicts.

RMSNorm

Before the LM head, each position's vector is rescaled to a standard size. For one row x of length D:

rms(x) = sqrt( mean(x²) + ε )    y = (x / rms(x)) ⊙ w

w is a learned (D,) vector (key model.norm.weight), and ε = 10⁻⁶ (rms_norm_eps). The ε sits inside the square root. If a row's mean square is far below ε, the ε dominates and keeps the division finite. One of the tests feeds tiny inputs to check exactly that. RMSNorm comes from Zhang & Sennrich (2019): LayerNorm without the mean subtraction, cheaper and just as good. The reference you are matching is Qwen3RMSNorm in HF's modeling_qwen3.py.

The LM head

To score every vocabulary entry, take each position's final vector and dot it with every token's vector: logits = y @ Eᵀ, shape (T, D) @ (D, V) = (T, V). Qwen3-0.6B ties its embeddings: the LM head reuses the same E as the embedding lookup. A token's logit is how well the final vector lines up with that token's own embedding. E holds 151,936 × 1024 ≈ 156M parameters, about a quarter of the model. The model card lists 0.6B total and 0.44B non-embedding. Tying saves another 156M.

Softmax, and why the naive one breaks

softmax(z)ᵢ = exp(zᵢ) / Σⱼ exp(zⱼ)

Exponentiating makes every score positive, and dividing by the sum makes each row add up to 1. Written naively, it breaks: fp32 tops out around 3.4 × 10³⁸ ≈ e88.7, so exp(89.0) is already inf, and inf / inf is NaN.

The fix comes from one line of algebra. For any constant c:

exp(zᵢ − c) / Σⱼ exp(zⱼ − c) = (exp(zᵢ)/ec) / (Σⱼ exp(zⱼ)/ec) = softmax(z)ᵢ

So you can subtract anything you like from a row first. Choose c = max(z). The largest exponent becomes exp(0) = 1 and the rest fall in (0, 1], so nothing overflows, and the denominator is at least 1, so you never divide by zero. Online softmax, the trick behind FlashAttention in stage 8, is this same max-subtraction done on the fly, while the row is still streaming in.

Predict first

Your zero-layer model is embed → RMSNorm → LM head, with nothing in between. Prompt: "The capital of France is". At the last position, which token will it rank first, and why? Write a guess before you run anything.

It predicts the token it was just given. After ' is' the top pick is ' is', after ' France' it is ' France', each with probability ≈ 1.00. Over a 272-token paragraph, measured on your 4050, the argmax was the current input token at 271 of 272 positions.

Why: with tied weights, the logit for candidate j is (a rescaled copy of et) · ej, and a vector lines up best with itself. The runners-up are its nearest neighbours in embedding space: 'France', ' france', '法国'. The one miss is a nice illustration: after ' their' the top pick was '他们的', Chinese for "their", with ' their' 0.9 logits behind. Translations end up as near neighbours.

The deeper reason is that a model with no middle can at best learn a bigram table (Elhage et al., below). With tied weights it can't even do that, because the score table E diag(w) Eᵀ is symmetric up to a per-row scale: "of → the" has to score the same as "the → of", and every token's own entry dominates its row. So every bit of next-token knowledge in this model lives in the 28 blocks you skipped. The real model's answer after ' is' is ' Paris' at 0.66.

One more measurement: those self-scores are around 116, past the e88.7 fp32 limit. A naive softmax returns NaN on this model's real output, not only on the contrived test.

Recall

From memory, without scrolling up.

Why does a stable softmax subtract the row max first?

Subtracting a constant doesn't change the result (the ec cancels), and with c = max every exponent is ≤ 0, so exp can't overflow.

Row t of the logits scores candidates for which token?

Each row is a next-token prediction made from the prefix ending at t. During generation only the last row gets sampled, which stage 3 will turn into a big saving.

Where does ε go in RMSNorm, and what does it guard against?

sqrt(mean(x²) + ε). When mean(x²) is far below ε, ε dominates and keeps the divisor away from zero.

Why is the embedding an index lookup and not a one-hot matmul?

Both give the same result. The one-hot version does T × V × D multiply-adds, nearly all by zero, just to copy T rows.
