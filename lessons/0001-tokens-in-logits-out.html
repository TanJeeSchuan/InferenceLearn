Tokens in, logits out

Build both ends of Qwen3-0.6B and leave out the middle. About 45 minutes.

Warm-up

There's nothing to review yet, so this checks the shape intuition you said you have. Answer from memory.

E has shape (151936, 1024) and ids has shape (6,). What shape is E[ids]?

Indexing with a tensor of ids picks whole rows, one per id, in order. Each of the 6 rows keeps its 1024 columns.

x is (6, 1024) and E is (151936, 1024). What shape is x @ E.T?

(6, 1024) @ (1024, 151936). The inner 1024s cancel and the outer dims survive, giving one number per position and vocabulary entry.

x is (6, 1024). What shape is x.mean(dim=-1, keepdim=True)?

With keepdim=True the reduced dim stays as size 1, so x / x.mean(-1, keepdim=True) divides each row by its own mean. Without it you get (6,), which broadcasts against the columns and gives the wrong answer or an error.

The whole job is one function

At inference time an LLM computes one function.

model(ids: (T,) int64) -> logits: (T, V) float

T is the number of tokens in the prompt. V is the vocabulary size, 151,936 for Qwen3-0.6B. Row t of the output scores every vocabulary entry as a candidate for token t+1, given tokens 0..t. These raw scores are logits, and softmax turns a row of them into probabilities. Every number about this model comes from its config.json. vocab_size is 151936, hidden_size 1024, num_hidden_layers 28, and tie_word_embeddings is true.

Generating text means calling this function, sampling from the last row, appending the sampled id and calling it again. That loop is stage 2. Everything after it, from the KV cache to batching and paging, makes the loop cheaper. Today you build the function without its middle.

  1. Tokenizer turns text into idsborrowed from Hugging Face(T,)
  2. Embedding lookupyou write it(T, 1024)
  3. 28 transformer blocksskipped today(T, 1024) → (T, 1024)
  4. Final RMSNormyou write it(T, 1024)
  5. LM headyou write it(T, 151936)
  6. Softmaxyou write it(T, 151936)

Text to ids

A tokenizer splits text into pieces from a fixed vocabulary and returns their integer ids. Qwen's tokenizer is byte-level BPE, so it can encode any byte sequence and never needs an "unknown" token. You won't write one. It has no effect on inference speed, and the model only ever sees the ids. The Qwen3 Technical Report describes the tokenizer in §2. len(tok) is 151,669, but the embedding table has 151,936 rows. The tokenizer never produces the last 267.

from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained("Qwen/Qwen3-0.6B")
ids = tok("The capital of France is", return_tensors="pt").input_ids[0]
print(ids, [tok.decode(i) for i in ids])

Ids to vectors

The embedding table E has shape (V, D), one learned 1024-number vector per vocabulary entry. Embedding a token means reading its row, E[ids].

Multiplying a one-hot matrix by E gives exactly the same result, one_hot(ids, V) @ E. Nobody does it that way. The one-hot version spends T × 151936 × 1024 multiply-adds, almost all of them by zero, to copy T rows. For T = 6 that is about 0.9 billion multiply-adds to move 6 × 1024 numbers. Stage 3 is about exactly this tension between doing math and moving bytes.

The middle, skipped

Each of the 28 blocks takes a (T, D) tensor and returns another (T, D) tensor. The shape never changes, so you can delete all 28 and the two ends still connect. Today you do that and look at what a model with nothing in the middle predicts.

RMSNorm

Before the LM head, each position's vector gets rescaled to a standard size. For one row x of length D:

rms(x) = sqrt( mean(x²) + ε )
y = (x / rms(x)) ⊙ w

w is a learned vector of length D, stored under model.norm.weight. ε is 10⁻⁶, from rms_norm_eps. Put ε inside the square root. When a row's mean square is far below ε, ε takes over and keeps the division finite, and one of the tests feeds tiny inputs to check that. The decoder has this formula worked through with numbers. RMSNorm comes from Zhang and Sennrich, 2019. It is LayerNorm without the mean subtraction. You are matching Qwen3RMSNorm in Hugging Face's modeling_qwen3.py.

The LM head

To score every vocabulary entry, dot each position's final vector with every token's vector. That is logits = y @ Eᵀ, and the shapes go (T, D) @ (D, V) = (T, V). Qwen3-0.6B ties its embeddings, meaning the LM head reuses the same E as the lookup. A token's logit measures how well the final vector lines up with that token's own embedding. E holds 151,936 × 1024 ≈ 156M parameters, about a quarter of the model. The model card lists 0.6B total and 0.44B non-embedding. An untied head would cost another 156M.

Softmax, and why the naive one breaks

softmax(z)ᵢ = exp(zᵢ) / Σⱼ exp(zⱼ)

Exponentiating makes every score positive. Dividing by the sum makes each row add up to 1. Written naively, it breaks. The largest fp32 number is about 3.4 × 10³⁸ ≈ e88.7, so exp(89.0) is already inf, and inf / inf is NaN.

One line of algebra fixes it. For any constant c,

exp(zᵢ − c) / Σⱼ exp(zⱼ − c)
= (exp(zᵢ) / ec) / (Σⱼ exp(zⱼ) / ec)
= softmax(z)ᵢ

So you can subtract anything you like from a row first. Pick c = max(z). The largest exponent becomes exp(0) = 1, the rest land between 0 and 1, and the denominator is at least 1. Nothing overflows and nothing divides by zero. The decoder shows both versions side by side with numbers. FlashAttention in stage 8 relies on online softmax, which does this same max subtraction while the row is still streaming in.

Predict first

Your zero-layer model runs embed, then RMSNorm, then the LM head, with nothing in between. The prompt is "The capital of France is". At the last position, which token will it rank first, and why? Write a guess before you run anything.

It predicts the token it was just given. After ' is' the top pick is ' is', after ' France' it's ' France', each at probability ≈ 1.00. Over a 272-token paragraph, measured on your 4050, the argmax was the current input token at 271 of 272 positions.

Tied weights are why. The model scores candidate j by dotting ej with a rescaled copy of the input's own embedding et, and a vector lines up best with itself. The runners-up are its nearest neighbours in embedding space, 'France', ' france' and '法国'. The one miss was after ' their', where the top pick was '他们的', Chinese for "their", with ' their' 0.9 logits behind. Translations end up as neighbours.

Elhage et al. show that a model with no middle can at best learn a table of bigram statistics. With tied weights it can't even do that. The score table E diag(w) Eᵀ is symmetric up to a per-row scale, so "of → the" has to score the same as "the → of", and every token's own entry dominates its row. Everything this model knows about what comes next lives in the 28 blocks you skipped. The full model's answer after ' is' is ' Paris' at 0.66.

One more measurement. Those self-scores sit around 116, well past the e88.7 limit. A naive softmax returns NaN on this model's real output, not only on the contrived test.

Recall

From memory, without scrolling up.

Why does a stable softmax subtract the row max first?

Subtracting a constant doesn't change the result because the ec cancels. With c = max every exponent is at most 0, so exp can't overflow.

Row t of the logits scores candidates for which token?

Each row predicts the next token from the prefix ending at t. Generation only samples the last row, and stage 3 turns that into a big saving.

Where does ε go in RMSNorm, and what does it guard against?

sqrt(mean(x²) + ε). When mean(x²) is far below ε, ε takes over and keeps the divisor away from zero.

Why is the embedding an index lookup and not a one-hot matmul?

Both give the same result. The one-hot version spends T × V × D multiply-adds, nearly all by zero, to copy T rows.
